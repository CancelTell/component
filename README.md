# COMPONENT — конструктор ПК с проверкой совместимости

Главный инструмент — конструктор: пользователь собирает компьютер по деталям, сайт проверяет совместимость и объясняет каждый результат. Каталог, сравнение и инструкция по сборке помогают в этом.

**Стек:** Next.js 15 (App Router) · React 19 · TypeScript (strict) · чистый CSS на дизайн-токенах · lucide-react · IBM Plex Sans + IBM Plex Mono через `next/font`.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # продакшен-сборка: страницы и /data/*.json генерируются статически
npm start
npm run typecheck
npm test           # правила совместимости, фильтры, поиск, ссылки на сборку (tests/*.test.ts)
```

Каждый пуш кода проверяет GitHub Actions (`.github/workflows/ci.yml`): типы, тесты, робот на тестовых данных и полная сборка. Если что-то сломано, в репозитории появится красный крестик у коммита.

Для продакшена задайте адрес сайта (canonical, sitemap, OG): `NEXT_PUBLIC_SITE_URL=https://example.com`.

## Архитектура данных

Каталог **не попадает в JS-бандл**. Правило:

- `@/data` (`src/data/index.ts`) и `@/data/offers` — **только для серверных компонентов** (страницы, метаданные, sitemap).
- Клиентские компоненты берут конфигурацию из `@/data/categories`, а данные — из `@/lib/catalog-client`: страница категории передаёт свою категорию в props (и кладёт её в кэш), конструктор, «Мои сборки» и сравнение подгружают `/data/<category>.json` по мере надобности (`useCatalog([...])`), поиск в шапке — `/data/search.json` при первом фокусе.
- Есть ли цены, браузер узнаёт из `NEXT_PUBLIC_HAS_PRICES` (ставит `next.config.ts` по `data/offers.json`). Пока цен нет, сайт их не показывает вообще: ни выдуманных цен, ни подбора под бюджет.

```
src/
  app/                  маршруты, metadata, OG-картинки, /data/[file] (статичный JSON)
  components/
    build/              BuildView (конструктор), PartPicker (выбор детали), CheckList, BuildStarter
    builds/             BuildsView («Мои сборки»)
    catalog/            CatalogView (таблица/карточки), FacetPanel, ProductCard, PriceLine, CompareButton
    home/               Hero (готовые сборки), PresetCard, CategoryList
    layout/ product/ compare/ search/ guide/ ui/
  data/
    categories.ts       категории: группы характеристик, колонки таблицы (tableSpecs), фильтры (facets), быстрые фильтры (quick)
    platforms.ts        чипсеты по сокетам и правила «нужно обновить BIOS»
    presets.ts          готовые сборки
    index.ts, offers.ts серверный доступ к data/catalog.json и data/offers.json
  lib/
    compatibility.ts    проверки совместимости (чистые функции)
    catalog-client.ts   кэш категорий в браузере, useCatalog
    catalog.ts          фасеты, сортировка, фильтры ⇄ URL, форматирование
    build-store.ts, saved-builds.ts, compare-store.ts   состояние в localStorage
```

**Фильтры** строятся из самих данных: `facets` в `categories.ts` — ключ характеристики и тип (`enum` — список значений с количеством, `range` — от/до). Новый сокет или бренд появляется в фильтре сам.

**Проверки совместимости** (`src/lib/compatibility.ts`), у каждой — статус, строка причины и «Подробнее»:
процессор ↔ плата (сокет + BIOS по `platforms.ts`), процессор ↔ память, плата ↔ память (тип и число модулей), мощность БП (формула показывается), разъёмы питания видеокарты (12V-2x6), кулер ↔ процессор (крепление, рассеиваемая мощность), кулер ↔ корпус (высота/радиатор, высокая память под башней), накопители ↔ слоты M.2, корпус ↔ плата, корпус ↔ видеокарта.
Статусы одинаковые везде: подходит (зелёный ✓), замечание (жёлтый !), не подходит (красный ✕), **не проверено** (серый ?) — когда в данных нет нужного значения; догадок вместо данных нет.

**Визуальный язык:** нейтральная графитовая палитра, один синий акцент для действий, статусные цвета только для статусов (`styles/tokens.css`), шкала шрифта 13/14/16/20/28, табличные цифры, анимации не длиннее 200 мс.

## Инструкция по сборке (`/guide`)

9 шагов с векторными анимациями. Сцены — `src/components/guide/scenes-*.tsx`, ключевые кадры — `timeline.ts` (`tr()`, `show`, `draw`, `ring`), плеер — `GuideView.tsx` (пауза вне экрана, `?step=cpu`, отметки «сделано», ← → и пробел).

## Готовые сборки и подбор

- `src/data/presets.ts` — готовые сборки (главная и конструктор).
- `src/lib/auto-build.ts` — подбор под бюджет; включается сам, когда появятся цены магазинов.
- `src/lib/share.ts` — ссылка на сборку.

## Данные: каталог и цены обновляются сами

```
Фиды магазинов (YML) ─┐                         ┌─ data/catalog.json      ← модели и характеристики
Open Icecat (JSON) ───┼─ scripts/pipeline ─────┼─ data/offers.json       ← цены по магазинам
data/overrides.json ──┘   (GitHub Actions)      ├─ data/price-history.json
                                                └─ data/report.md        ← что не удалось добавить
            коммит в репозиторий → Vercel пересобирает сайт
```

- **Каталог** (`npm run data:catalog`, раз в сутки):
  - процессоры и видеокарты (чипы) — из таблиц английской Википедии (`scripts/pipeline/wikipedia.ts`); страницы — в `data/import-config.json`;
  - платы, память, SSD, блоки питания, кулеры, корпуса — из общего списка Open Icecat (`icecat-index.ts`), по `perCategory` новых карточек за запуск на категорию;
  - фиды магазинов показывают, какие модели продаются, и дополняют характеристики. Модель публикуется, только если известны поля для проверки совместимости (`REQUIRED` в `normalize.ts`), иначе попадает в `data/report.md`.
- **Цены** (`npm run data:prices`, каждые 4 часа): предложения привязываются к моделям по штрихкоду, коду производителя или названию; видеокарты — по чипу (все версии RTX 4060 → одна модель, цена «от»). Сохраняется самое дешёвое предложение в наличии на магазин и точка истории цен за день.
- **Ручные правки**: `data/overrides.json` — исправить характеристику, добавить код модели, скрыть модель. Главнее автоматики.
- **Ручные модели**: `src/data/products/*.ts` — всегда попадают в каталог.
- **Проверка без ключей**: `npm run data:test` — прогон на тестовых фидах из `scripts/pipeline/fixtures`, результат в `.cache/test`.
- **Пока цен нет**, `data/offers.json` пуст и сайт цены не показывает; первая настоящая выгрузка включает их сама (после пересборки сайта).

Переменные окружения (GitHub → Settings → Secrets and variables → Actions):

| Секрет | Откуда |
|---|---|
| `ICECAT_USERNAME` | логин Open Icecat (бесплатная регистрация) |
| `ICECAT_PASSWORD` | пароль Open Icecat — нужен для общего списка товаров |
| `ICECAT_API_TOKEN` | необязательно, токен из кабинета Icecat |
| `FEED_DNS`, `FEED_OZON`, `FEED_CITILINK`, `FEED_MVIDEO` | ссылки на товарные фиды (YML) из партнёрской сети |

Что нашлось в Википедии и Icecat (таблицы, колонки, категории) — в `data/sources-report.md`.

Новые характеристики учатся так: в `data/report.md` есть список нераспознанных параметров — для нужных добавьте правило в `RULES` (`scripts/pipeline/normalize.ts`).

## Данные

У каждой модели в `catalog.json` есть `source` (`manual`, `wikipedia`, `icecat`, `store`), `updatedAt` и, если Icecat отдаёт фото, `image` — сайт показывает их на странице модели. Где фото нет, стоит нейтральная иконка категории. Длина видеокарт известна только для эталонных версий; для чипов из Википедии её нет, и конструктор честно просит сверить длину версии карты.

«Сообщить об ошибке» открывает готовую форму issue в репозитории (`siteConfig.repo` в `src/lib/site.ts`).

## Превью без Next.js

Папка `preview/` — служебная: собирает те же страницы в один HTML-файл с хеш-роутингом (через esbuild и заглушки для `next/*`), чтобы показать дизайн без сервера. В приложение она не входит и может быть удалена.
